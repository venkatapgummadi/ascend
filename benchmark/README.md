# ASCEND public benchmark harness

This harness produces the numbers for the **CARS 2026 / AI²** paper from
**public, reproducible inputs only**. It deliberately does *not* use the
NDA-protected per-repository telemetry referenced in the main repo's
`evaluation/README.md`, and it does *not* reproduce the withdrawn IEEE Access
field-study figures (83% / 43.5% / 94.2% at p<0.001). Every number it emits can
be regenerated by anyone from the listed public artifacts.

It fills exactly the `%%<<FILL>>` placeholders in `ASCEND_CARS2026.tex`:

| Paper item | Script | Output |
|---|---|---|
| Table II — detection coverage | `run_coverage.py` | `results/coverage.json` + LaTeX rows |
| Tool complementarity sentence | `run_coverage.py` | combined / best-single / marginals |
| Synchronization (auto-resolve rate, conditional accept-rate, by type) | `run_sync.py` | `results/sync.json` + LaTeX |
| Overhead (per-layer CI minutes) | `run_overhead.py` | `results/overhead.json` + LaTeX |

## What is measured (and why it's honest)

1. **Detection coverage** is measured on a *labeled* benchmark (OWASP Benchmark),
   so true-positive rates are computed against known ground truth — not against
   private repos with hand-curated labels. Single-tool vs. multi-tool coverage and
   the marginal value of each added tool fall straight out of the join.
2. **Synchronization** is measured on the repo's own public
   `examples/conflict-fixtures/` plus (optionally) conflicts *mined from public
   repositories listed by commit hash*. The classifier/resolver is run on data
   **disjoint** from any training corpus you use, which removes the train/test
   leakage Reviewer 1 flagged. The headline accept-rate is reported **conditional
   on auto-resolution**, with the auto-resolve rate stated separately.
3. **Overhead** is wall-clock time of each scanning layer on the bundled sample
   apps, repeated `--runs` times; we report median and P95.

## Install

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
# Scanners (install the ones you will report):
pipx install semgrep checkov         # or: pip install semgrep checkov
pip install bandit
# Trivy / Gitleaks: install per their docs (binaries).
# CodeQL / SonarQube: optional; see ground_truth_rules.md for adapters.
```

## Run

```bash
# 1) Detection coverage on the labeled benchmark
#    (clone OWASP Benchmark first; see benchmarks.yaml)
python run_coverage.py --benchmark ./_data/owasp-benchmark \
                       --sarif-dir ./_data/sarif --out results/coverage.json

# 2) Synchronization metrics on public fixtures (+ optional mined conflicts)
python run_sync.py --fixtures /path/to/ascend/examples/conflict-fixtures \
                   --tau 0.85 --bootstrap 10000 --out results/sync.json

# 3) Scanning overhead on sample apps
python run_overhead.py --app /path/to/ascend/examples/sample-python-app \
                       --runs 5 --out results/overhead.json

# 4) Emit LaTeX rows to paste over the %%<<FILL>>% placeholders
python gen_latex.py results/coverage.json results/sync.json results/overhead.json
```

## Honesty rules (read before pasting numbers into the paper)

- Report whatever the harness prints. If a tool finds little, that is the result.
- Keep the accept-rate's "conditional on auto-resolution" wording; do not promote
  it to a general accuracy figure.
- Name the exact OWASP Benchmark version, the fixture commit, and (if used) the
  public training corpus and the disjoint mined-conflict repos in the paper.
- Do **not** reinsert the withdrawn field-study numbers from `docs/paper/`.
